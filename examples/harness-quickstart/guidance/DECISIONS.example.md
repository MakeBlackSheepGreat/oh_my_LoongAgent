# 关键决策记录（示例模板）

## D-001：项目以可用系统为优先交付

**日期**：2026-08-01  
**决定**：论文、综述与汇报从系统运行、实验与复盘中沉淀。  
**影响**：每个新增模块需要先证明用户价值、可靠性、成本或治理收益。

## D-002：通信以动作契约和工件引用为核心

**日期**：2026-08-01  
**决定**：Agent 交换结构化任务状态、工件 URI、版本、证据与验证结果。  
**影响**：完整自然语言讨论按需使用；运行时必须支持溯源、回放和过期状态识别。

## D-003：验证器驱动预算分配

**日期**：2026-08-01  
**决定**：新增检索、候选、修复、审查和云端升级应由风险、验证反馈、候选分歧与剩余预算共同触发。  
**影响**：系统闭环实现结构化契约、验证器与预算感知策略，并与固定策略进行对照。

## D-004：经验必须先回放再进入长期库

**日期**：2026-08-01  
**决定**：成功或失败轨迹只有在固定环境回放并通过检查后，才能成为 skill 卡片、测试夹具、偏好样本或轻量后训练候选。  
**影响**：经验库维护版本、来源、适用范围、验证条件与失效状态。

## D-005：项目指导文件采用职责分层

**日期**：2026-08-01  
**决定**：`AGENTS.md` 负责路由，`SOUL.md` 负责主观风格，`RULES.md` 负责硬边界，`SPEC.md` 与 `specs/` 负责任务计划，`IDEA.md` 负责候选创新。  
**影响**：同一内容只保留在对应职责文件；Agent 按核心指引规定的顺序读取。

## D-006：来源登记与项目许可成为发布门

**日期**：2026-08-01  
**决定**：建立 `ATTRIBUTIONS.md` 作为论文、代码、既有资产与许可状态的唯一来源登记；项目原创代码和文档采用 Apache License 2.0。  
**影响**：研究结论必须指向已登记论文；外部代码进入核心运行时前必须确认版本、许可和归属；发布前检查 `LICENSE`、`NOTICE` 和登记记录。

```md
**影响**：[对项目、架构、路线或约束的影响]
```
