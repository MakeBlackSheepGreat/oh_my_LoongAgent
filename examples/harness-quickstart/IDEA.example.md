# 项目候选创新与实验方向（示例模板）

本文件只保存候选创新点、创新方向、可检验假设与实验思路。项目要求、代码口味、硬边界、任务计划、进度记录和已采纳决策分别由 `SOUL.md`、`RULES.md`、`SPEC.md`、`specs/` 与 `guidance/DECISIONS.md` 管理。

所有条目在完成直接文献比较、可复现基线和保留集实验前，均保持"候选"状态。

## I-001：基础执行层与条件升级

**提出时间**：2026-08-01  
**状态**：候选

**创新方向**：让轻量级模型承担边界清楚、高频、可验证、可撤销的节点；复杂规划、高不确定性和高风险任务按条件升级给云端模型或人工。

**实验方向**：为任务标注复杂度、风险、可验证性和工具依赖，比较全本地、固定阈值升级、学习式升级与强模型全覆盖。

## I-002：动态协作触发器

**提出时间**：2026-08-01  
**状态**：候选

**创新方向**：将多 Agent 协作视为有成本的运行时动作。只有子目标可独立验收、单 Agent 不确定性升高、工具失败需要隔离诊断、风险需要独立审查或任务适合并行时触发协作。

**实验方向**：对比单 Agent、固定角色、规则触发、学习式触发和熵驱动触发。

## I-003：任务契约与工件引用通信

**提出时间**：2026-08-01  
**状态**：候选

**创新方向**：设计结构化任务契约，让 Agent 交换任务 ID、目标、输入工件、输出 Schema、状态增量、证据、权限、错误码和下一动作。自然语言协商只在语义冲突时按需发生。

**实验方向**：与全量聊天、阶段摘要和共享黑板对比，测量 token、Schema 合法率、状态一致性、错误复现率、隐私泄露检测率和恢复成功率。

