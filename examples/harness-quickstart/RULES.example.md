# 项目边界与禁止事项（示例模板）

**版本**：v0.1  
**生效日期**：2026-08-01

本文件定义硬约束。任何 Agent、代码、实验和文档均须遵守；需要修改时，由用户明确批准，并在 `guidance/DECISIONS.md` 记录原因与影响。

## 技术边界

- 后端唯一主线语言为 Go；前端唯一主线技术栈为 TypeScript + Vue。
- 禁止在核心项目中引入其他未经批准的主语言或前端框架。
- 多平台支持：必须支持 Windows、Linux、macOS 三种操作系统。
- 多架构支持：必须支持 x86（amd64）、ARM（arm64）、龙芯（loongarch64）、RISC-V（riscv64）四种 CPU 架构。
- 构建产物必须以 `CGO_ENABLED=0` 单静态二进制方式分发，确保跨平台跨架构可编译。
- 编译与测试必须在所有目标平台与架构组合上可执行；CI 或发布前必须覆盖至少 Windows/amd64、Linux/amd64、Linux/arm64、macOS/arm64 四组合。
- 禁止使用 cgo 或平台专有绑定，除非该能力无法以纯 Go 实现；若必须引入，需在 `guidance/DECISIONS.md` 记录并限定隔离边界。
- 禁止让模型生成的自由文本直接触发工具；所有动作必须先通过类型化契约、Schema 和权限检查。
- 禁止以无界自然语言群聊作为运行时状态源；状态必须落到版本化工件或结构化事件。
- 禁止无上限重试、无上限候选生成和无预算的 Agent 并发。
- 禁止为了潜在未来需求提前建立复杂抽象、微服务或分布式基础设施。

## 模型与数据边界

- 核心可复现实验限定为目标模型范围内，本地主基线优先使用轻量级模型。
- 云端 API 必须记录供应商、端点、模型标识、日期、参数、token、成本、限流和数据等级。
- 禁止采集、要求、保存或训练隐藏推理链；仅使用计划、动作、工具参数、观察、工件、验证结果和错误码等可观察数据。
- 禁止把私密文件、凭据、个人身份信息和未脱敏实验材料发送到未经批准的云端服务。
- 禁止把供应商的动态模型版本当作本地核心实验的固定前提。

## 工具与安全边界

- 禁止在真实支付、账户变更、医疗、法律或其他高风险系统中执行无人审批动作。
- 高风险实验只在模拟环境运行；提交动作需要明确人工批准。
- 禁止绕过工作区、最小权限、路径检查、Schema 校验、审计和回滚机制。
- 禁止执行范围含糊的删除、覆盖、批量移动或外部发布操作。
- 工具失败必须产生结构化错误码；模型解释不能覆盖真实工具结果。

## 研究诚信边界

- 禁止捏造论文、引用、实验数据、模型能力、运行结果或开放源代码状态。
- 禁止在缺少直接文献比较和消融证据时使用"首个""首次""达到前沿"等强声明。
- 禁止用单次最佳结果代表系统能力；必须保存重复运行、均值、方差、成本和失败案例。
- 禁止在不同预算、权限、工具或任务条件下做未经说明的横向比较。
- 禁止将特定任务得分接近强模型描述为通用能力等价。

## 来源与许可边界

- 支撑研究主张、设计选择、实验协议或基准比较的外部论文、数据集、模型报告和公开网页，必须登记在 `ATTRIBUTIONS.md`，并在使用该主张的报告、论文或图表中给出可定位引用。
- 任何受外部代码、提示词、配置、测试夹具或实现方案实质影响的交付，必须在使用前登记来源 URL、版本或 commit、许可、使用路径、改动说明和需要保留的归属声明。
- 未核实来源、版本和许可状态的第三方代码不得进入核心运行时、发布包或实验基线。
- 复制、修改、再分发第三方材料时，必须保留上游许可、版权声明和所需 NOTICE；论文与模型报告的版权归原权利人所有，不随本项目许可转授。
- 项目原创代码和文档使用根目录 `LICENSE` 的 Apache License 2.0；目录级上游许可优先适用于对应第三方内容。

## 文件职责边界

- `IDEA.md` 只保存候选创新、创新方向、实验假设和可实验方向。
- 项目要求、代码规范、禁止事项只进入 `RULES.md`。
- 主观体验、视觉偏好和代码审美只进入 `SOUL.md`。
- 任务计划、进度、依赖和验收条件只进入 `SPEC.md` 与 `specs/`。
- 已采纳架构取舍只进入 `guidance/DECISIONS.md`。
- 外部文献、代码、既有资产和许可状态只进入 `ATTRIBUTIONS.md`；项目自身许可与必要第三方声明位于 `LICENSE` 和 `NOTICE`。
- 禁止在多个指导文件中维护互相冲突的同一规则。
