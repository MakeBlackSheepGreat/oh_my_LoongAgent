## R-001：交付脚本未经实际执行验证（2026-08-01，用户要求自查 dev.ps1）

**问题**：用户要求自查"一键启动开发模式"脚本（`dev.ps1`）。实测发现脚本**从未成功运行过**，存在两个致命 bug：

1. `catch { /* 服务尚未就绪 */ }` —— PowerShell 不支持 C 风格注释，运行时把 `/*` 当作命令执行并抛错（语法解析能通过，但**运行时崩溃**）。健康检查等待期间第一次连接失败即触发。
2. `Start-Process -RedirectStandardOutput $log -RedirectStandardError $log` —— PowerShell 禁止 stdout/stderr 重定向到同一文件，直接抛 `InvalidOperationException`，脚本在后端启动阶段即退出。

**根因**：交付脚本时只"读代码 + 推理"，没有实际执行验证。语法解析（ParseFile）通过不等于可运行——`/*` 是运行时错误不是语法错误。

**防再犯措施**：
- **任何脚本/命令/构建产物的交付必须实际执行验证**（语法检查 + 至少一条关键路径运行），不能只靠读代码判断可用。
- 对脚本语言（PowerShell/bash）必须了解其与 C 系语言的语法差异：注释、错误处理、重定向语义。
- 验证结果写入 SPEC/任务验收证据，而不是口头声称"应该能用"。

**修复**：`dev.ps1` 修复后完整运行验证：后端 `/health` 200、前端 48623 200、Vite 代理 200；停止逻辑用 `taskkill /PID /T /F` 杀整棵进程树（`go run` 会派生 server 子进程，`Kill()` 只杀父进程会残留端口占用）。README 中与真实接口不符的 `serve` 子命令说明同步修正。

## R-002：bash 调用 powershell.exe 内联命令时 `$` 变量被剥掉（2026-08-01，自查 dev.ps1 过程中）

**问题**：本工作环境（git-bash）中执行 `powershell.exe -Command '...$var...'`，无论单引号还是 `\$` 转义，`$var` 都会被剥成空串，导致命令解析错误或错误输出。本次任务中**连续踩了 3 次**才确认根因（前两次误以为是引号问题）。

**正确做法**：
- bash 里调用 powershell 带 `$` 变量的逻辑，**一律写成临时 `.ps1` 文件**，用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File xxx.ps1` 执行，用完删除。
- 无 `$` 的简单内联命令（如纯 `Get-NetTCPConnection ... | Select-Object`）可以直接 `-Command`。

**防再犯措施**：所有 PowerShell 交互检查默认走临时文件路径，不再尝试内联 `$` 转义。

## R-003：前端交付未做真实浏览器端到端验证（2026-08-01，用户指出前端质量差）

**问题**：用户报告"前端白茫茫一片、很多组件没显示、点击模型供应商没反应、创建账号没有账号密码要求、没有登录页面"。实测定位四个真实 bug：

1. `InitAll()` 漏调 `InitUsageTable()` → `usage_events` 表从未创建 → 用量 API 全部 500。
2. 列表 API 空数据时 Go 的 nil slice 序列化为 JSON `null` → 前端 `state.conversations = null` → 模板 `null.length` 渲染崩溃（Vue unhandled error），组件树部分失效——这就是"白屏/组件不显示"。
3. 前端创建供应商不传 `profile_id`，而后端要求非空 → 一键添加 400"没反应"。
4. 认证体系是"点选账户列表、无密码"设计，用户明确要求账号密码登录/注册。

**根因**：之前交付前端只验证了 `npm run build` 能过（编译期），**从未用真实浏览器做端到端操作验证**（注册→进工作台→点各面板→登出）。三个 bug 全是运行期问题，编译期永远发现不了。认证设计也偏离了用户对"账号密码"的直觉预期。

**防再犯措施**：
- **前端功能交付必须 playwright（或等价真实浏览器）端到端实测**：注册/登录 → 各面板点击 → 核心 API 全部 200 → 无 console 报错，并把验证截图/console 日志作为证据。
- 后端列表类 API 统一返回 `[]` 而非 `null`（已修复 5 处）；前端 store 统一 `?? []` 兜底。
- 契约不一致（客户端请求体 vs 服务端校验）必须由端到端实测覆盖，不能只靠单测。
- 用户可见交互（登录/注册方式）默认遵循用户直觉（有账号密码），有设计偏差先问用户。

**修复**：usage 表初始化、5 处 List 返回 `[]`、前端 `?? []` 兜底、`profile_id` 服务端生成、完整账号密码体系（PBKDF2 哈希 + 注册/登录改造 + 登录页重写 + i18n）；playwright 全流程实测通过（注册→工作台→供应商添加 201→usage 200→登出→错误密码 401→正确密码登录成功）。

## R-004：创建 git 仓库时未排除参考文献/大二进制等外部资产（2026-08-01，用户指出）

**问题**：用户要求创建 git 仓库并推送到 GitHub。首次提交把 `literature_archive/` 下 **60 个文献 PDF（约 154MB）** 全部推了上去。用户连续两次指出："你没有排除pdf文件吗？"、"排除缓存文件，排除密钥文件，排除参考文献，这些都是基本常识吧？"

**根因**：创建仓库时只做了 `.gitignore` 的基础完善（工具目录、构建产物），**没有做入库内容审计**——没有检查已暂存文件中的大文件、二进制、外部资产（PDF/PPTX/压缩包）、凭据类文件。README 也把 `literature_archive` 列为仓库内容而没有区分"外部资产不随仓库分发"。

**防再犯措施**（硬性清单，创建/更新 git 仓库时逐项执行）：
1. **外部资产不入库**：参考文献、下载的论文、素材包等（有来源可追溯、可重新获取的文件）默认排除；项目内只保留引用/清单（如 ATTRIBUTIONS.md）。
2. **缓存文件不入库**：`__pycache__`、`.pytest_cache`、`*.tsbuildinfo`、`node_modules`、构建产物（`dist/`）、工具状态目录（`.reasonix/.sisyphus/.trae/.workbuddy/.playwright*`）。
3. **密钥/凭据不入库**：`.env`、`*.pem/*.key/*.p12/*.pfx/*.crt`、token 文件；只保留 `.env.example` 占位。
4. **提交前审计**：`git ls-files` 按类型统计（大二进制/PDF/密钥/缓存），`git add` 前用 `git status` 检查暂存内容；大文件（>1MB）逐个确认是否必须入库。
5. 首次提交后**核对远程仓库体积**（gh api size 字段），异常偏大说明有未排除的大文件。

**修复**：`.gitignore` 新增 `literature_archive/**/*.pdf`；`git rm --cached` 移除 60 个 PDF（磁盘保留）；重新 force push；远程仓库 154MB → 834KB。
