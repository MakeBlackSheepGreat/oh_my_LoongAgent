# 关键决策记录

## D-001：项目以可用系统为优先交付

**日期**：2026-07-30  
**决定**：论文、综述与汇报从系统运行、实验与复盘中沉淀。  
**影响**：每个新增模块需要先证明用户价值、可靠性、成本或治理收益。

## D-002：单卡采用串行角色复用

**日期**：2026-07-30  
**决定**：同一个本地 8B/9B 模型可在路由、规划、执行、审查角色之间串行复用。  
**影响**：减少显存常驻；云端并发仅投向互不依赖的子任务并记录资源数据。

## D-003：通信以动作契约和工件引用为核心

**日期**：2026-07-30  
**决定**：Agent 交换结构化任务状态、工件 URI、版本、证据与验证结果。  
**影响**：完整自然语言讨论按需使用；运行时必须支持溯源、回放和过期状态识别。

## D-004：验证器驱动预算分配

**日期**：2026-07-30  
**决定**：新增检索、候选、修复、审查和云端升级应由风险、验证反馈、候选分歧与剩余预算共同触发。  
**影响**：首个系统闭环实现 `DRA -> AAR -> AGI -> verifier -> BVAR`，并与固定策略进行对照。

## D-005：经验必须先回放再进入长期库

**日期**：2026-07-30  
**决定**：成功或失败轨迹只有在固定环境回放并通过检查后，才能成为 `skill_card`、测试夹具、偏好样本或轻量后训练候选。  
**影响**：经验库维护版本、来源、适用范围、验证条件与失效状态。

## D-006：项目指导文件采用职责分层

**日期**：2026-07-30  
**决定**：`AGENTS.md` 负责路由，`SOUL.md` 负责主观风格，`RULES.md` 负责硬边界，`SPEC.md` 与 `specs/` 负责任务计划，`IDEA.md` 负责候选创新。  
**影响**：同一内容只保留在对应职责文件；Agent 按核心指引规定的顺序读取。

## D-007：Soul 由既有作品与真实界面证据校准

**日期**：2026-07-30  
**决定**：以用户既有代码项目和经过审查的成熟信息产品界面，共同校准 `SOUL.md`。运行界面采用紧凑可靠的专业工作台气质；首页、实验报告和成果展示采用鲜明的编辑式视觉语言。  
**依据**：既有 Agent、医学影像、RAG、Skill 与 PCB 工作流持续体现端到端交付、显式契约、状态机、阶段门、审计、本地优先和渐进披露偏好。经审查的编辑式信息界面体现方格纸、大号衬线标题、无圆角框线、偏移阴影、高信息密度及多种高亮强调色；移动端结构稳定，但长页与首屏密度需要在本项目中主动控制。用户自主项目、fork 项目及上游贡献分别记录，避免把上游设计直接归入用户偏好。  
**影响**：后续界面设计先判断属于运行工作台或编辑展示层；代码评审同时关注产品闭环、契约、状态、失败路径、验证产物和渐进披露。硬性技术边界仍以 `RULES.md` 为准。

## D-008：来源登记与项目许可成为发布门

**日期**：2026-07-30  
**决定**：建立 `ATTRIBUTIONS.md` 作为论文、代码、既有资产与许可状态的唯一来源登记；项目原创代码和文档采用 Apache License 2.0。  
**影响**：研究结论必须指向已登记论文；外部代码进入核心运行时前必须确认版本、许可和归属；发布前检查 `LICENSE`、`NOTICE` 和登记记录。

## D-009：通用 Harness 与首发 Skill 分离

**日期**：2026-07-31  
**决定**：项目本体为面向 12B 以下模型的通用 Agent Harness；论文搜索为首个 `literature_search` Skill Pack 和评测场景。BVAR 固定为 B4 策略，不定义框架边界。  
**影响**：核心层只能依赖任务、动作、工件、状态、预算、权限、验证与策略契约。论文、PDF、DOI、arXiv、Excel 导出等领域能力必须位于 Skill 层。至少以一个模拟文件整理 Skill 回归验证核心的领域无关性。

## D-010：强教师与交互运行时隔离

**日期**：2026-07-31  
**决定**：强模型仅生成或审核离线 `GoldReferencePack`；用户交互任务不得隐式调用教师。  
**影响**：记录教师可观察的查询、动作、工具观察、工件、验证和评分，不保存隐藏推理链；学生基准固定 Provider、模型和预算。

## D-011：项目中心工作台

**日期**：2026-07-31  
**决定**：本地工作台以多项目、连续人机对话和受控任务草案作为首屏组织方式。左侧承载项目与导航，中部承载聊天，右侧承载计划、输出、Agent、来源和上下文。论文搜索只作为首个 Skill 与评测场景。  
**影响**：项目、会话、草案、插件与本地根目录属于 `workbench/` 应用层；`harness/` 维持领域无关的运行时边界。模型消息必须先形成可见答复和结构化草案，用户批准后才能创建运行。

## D-012：供应商档案与 Coding Agent 工作台节奏

**日期**：2026-07-31  
**决定**：工作台采用项目根目录、任务会话、聊天主面、可观察阶段与右侧证据检查器的紧凑节奏。模型供应商以可持久化档案管理，档案存放端点、模型候选和环境变量密钥引用；当前激活档案可显式应用到项目与会话。  
**依据**：Codex 与 Claude Code 的公开产品资料体现了项目上下文、连续任务和阶段可见性的价值。CC Switch 的公开资料明确使用 SQLite 档案、激活切换、环境配置、健康监测和使用记录来管理多个 Agent 工具的供应商配置。  
**影响**：不复制第三方代码、品牌或账户管理流程；本项目只实现适合自身 OpenAI 兼容 Provider 的最小档案集。密钥继续只由环境变量读取，强教师继续隔离于交互运行时。

## D-013：后端以 Go 语言重写并纳入多用户体系

**日期**：2026-08-01  
**决定**：后端从 Python/FastAPI 迁移到 Go，参考 DeepSeek-Reasonix（MIT）的 Go agent harness 架构模式。重写与新需求合并推进：多用户账户隔离、公共模型池 token 计量、DeepSeek 定制化优化与 i18n 多语言。  
**依据**：用户要求服务化为多用户系统，Go 的 goroutine 并发模型、单静态二进制（`CGO_ENABLED=0`）分发与较低运行时内存更契合多账户并发与计量聚合场景。Reasonix 的 config-driven provider 声明、MCP 兼容 plugin 体系与 cache-aware context maintenance 提供了成熟的 Go harness 结构参考。在当前"等 LLM API"的 IO 密集负载下 Python 并非性能瓶颈，但多用户服务化方向使并发与内存成为可预见瓶颈，提前重写避免双栈维护。  
**影响**：
- 新建 `task14` 管理 Go 重写，拆分为核心迁移、多用户、计量、DeepSeek 定制、Skill adapter 与前端对接等子任务。
- `harness/`、`workbench/`、`skills/` 的 Python 实现保留作为迁移参考与并行对照基线，不删除直至 Go 版本通过对等测试。
- 核心契约（任务、动作、工件、状态、预算、权限、验证、策略）从 Pydantic 迁移到 Go struct + 验证标签，保持领域语义不变。
- DeepSeek 作为一等 provider preset，参考 Reasonix 的 prefix cache 稳定会话与 stale 输出剪枝做定制化优化；其他 OpenAI 兼容端点保持配置项身份。
- 多用户隔离与 token 计量从 Go 重写首日纳入，避免在 Python 版本上做过渡实现。
- 强教师隔离原则（D-010）在 Go 版本继续生效。
- 来源登记见 `ATTRIBUTIONS.md` C-007。

## D-014：删除 Python、切换前端为 Vue、确立多平台多架构唯一主线

**日期**：2026-08-01  
**决定**：
- 删除全部 Python 代码与构建配置，不做存档；Go 作为后端唯一主线语言。
- 删除 React 前端；TypeScript + Vue 3 作为前端唯一主线技术栈。
- 项目支持 Windows、Linux、macOS 三种操作系统与 x86（amd64）、ARM（arm64）、龙芯（loongarch64）、RISC-V（riscv64）四种 CPU 架构。
- 构建产物以 `CGO_ENABLED=0` 单静态二进制分发；禁止 cgo 或平台专有绑定。

**依据**：
- 用户要求 Go 作为唯一后端主线，删除 Python 不留存档，避免双栈维护成本与迁移犹豫。
- 前端从 React 切换到 Vue 3 + TypeScript，是用户明确的唯一前端主线选择。
- 多平台多架构支持面向龙芯、RISC-V 等国产与新兴架构，单静态二进制是最低分发成本方案。
- RULES.md v0.3 已写入上述硬约束。

**影响**：
- Python 目录（`harness/`、`workbench/`、`skills/`、`tests/`、`bvar/` 等）、`pyproject.toml` 与 Python 构建链全部移除。
- React 前端（`web/`）移除，新建 Vue 3 + TypeScript 前端骨架。
- task0-task13 的 Python 实现不再作为对照基线；Go 版本需独立完成全部迁移与验证。
- ATTRIBUTIONS.md C-004（Python 核心运行时依赖）标记为 retired。
- 后续 task14 子任务目标不变，但验收条件中"与 Python 版对等测试"改为"Go 版本独立通过全部测试"。
- 新增跨平台跨架构 CI 与交叉编译验证作为发布前强制门。
